# CS:APP Data Lab 学生实验说明

## 1. 实验目标

本实验包含 15 道题：10 道整数位运算题和 5 道浮点数题。你将只使用受限的 C 语言操作，直接处理整数和浮点数的二进制表示。

完成实验后，你应当能够：

- 理解 32 位二进制补码；
- 使用掩码、移位和布尔位运算处理位模式；
- 判断整数范围、符号和溢出；
- 解释 IEEE 754 binary32 的符号、指数和尾数字段；
- 区分零、非规格化数、规格化数、无穷和 NaN；
- 理解 AI 计算中使用的 FP8 E4M3 低精度格式；
- 使用自动测试程序定位错误并查看得分。

本实验是个人作业。每位学生必须独立完成并提交自己的 `bits.c`，不得以小组或 team 形式提交。

## 5. 编码规则

整数题和浮点题采用不同规则。开始写某个函数前，必须阅读 `bits.c` 中该函数上方的注释。

### 5.1 整数题

整数题只能使用：

- `0` 到 `255` 之间的整数常量；
- 函数参数和 `int` 局部变量；
- `!`、`~`、`&`、`^`、`|`、`+`、`<<`、`>>`。

禁止使用：

- `if`、`else`、`for`、`while`、`switch` 等控制结构；
- 宏、数组、结构体、联合体和全局变量；
- 新增函数或调用任何函数；
- `&&`、`||`、`-`、`*`、`/`、`%`、比较运算符和三目运算符；
- 任何形式的类型转换；
- 大于 `0xFF` 的直接常量。

赋值符号 `=` 不计入运算符数量。部分题目会进一步限制允许运算符。

### 5.2 浮点题

浮点题允许：

- `int` 和 `unsigned`；
- 任意整数常量；
- 整数运算、位运算和比较；
- `if`、`while`、`for` 等控制结构。

浮点题禁止：

- `float`、`double` 和浮点常量；
- 任何浮点运算；
- 类型转换；
- 宏、数组、结构体和 `union`；
- 调用任何函数。

浮点题中的整数参数和返回值表示原始位模式。例如，`0x3F800000u` 是 binary32 数值 `1.0` 的位模式，但不能在学生代码中写 `1.0f` 或把整数转换为 `float`。

| 函数 | 任务 | 输入约束 | 最大运算符数 | 分值 |
| --- | --- | --- | ---: | ---: |
| `bang(x)` | 将补码转换为 sign-magnitude（原码） | `x != TMin` | 12 | 4 |
| `dividePower2(x, n)` | 计算 `x / 2^n`，向 0 舍入 | `0 <= n <= 30` | 15 | 3 |
| `bitCount(x)` | 统计值为 1 的位数 | 任意 32 位整数 | 40 | 4 |
| `fitsBits(x, n)` | 判断 `x` 能否用 `n` 位补码表示 | `1 <= n <= 32` | 15 | 2 |
| `getByte(x, n)` | 提取第 `n` 个字节 | `0 <= n <= 3` | 6 | 2 |
| `isGreater(x, y)` | 判断 `x > y` | 任意 32 位整数 | 24 | 3 |
| `isNonNegative(x)` | 判断 `x >= 0` | 任意 32 位整数 | 6 | 3 |
| `logicalShift(x, n)` | 对 `x` 执行逻辑右移 | `1 <= n <= 31` | 16 | 3 |
| `satAdd(x, y)` | 执行饱和加法 | 任意 32 位整数 | 30 | 4 |
| `logicalNeg(x)` | 不使用 `!` 实现逻辑非 | 任意 32 位整数 | 12 | 4 |

位和字节都从最低有效位置开始编号，第 0 位是最低位，第 0 个字节是最低有效字节。

## 7. binary32 背景知识

浮点题使用 IEEE 754 单精度格式，也称 binary32。一个 binary32 位模式由三部分组成：

```text
31             30                    23 22                         0
+----------------+----------------------+----------------------------+
| 符号 S：1 位   | 指数 E：8 位         | 尾数 F：23 位               |
+----------------+----------------------+----------------------------+
```

指数偏置是 127。根据指数字段 `E` 的值，位模式分为：

| 指数字段 | 类别 | 数值含义 |
| --- | --- | --- |
| `E = 0`，`F = 0` | 正零或负零 | 符号由 `S` 决定 |
| `E = 0`，`F != 0` | 非规格化数 | 没有隐含的最高位 1 |
| `1 <= E <= 254` | 规格化数 | 有隐含的最高位 1，真实指数为 `E - 127` |
| `E = 255`，`F = 0` | 正无穷或负无穷 | 符号由 `S` 决定 |
| `E = 255`，`F != 0` | NaN | 表示“不是一个数” |

对于规格化数：

```text
value = (-1)^S × 2^(E-127) × (1 + F / 2^23)
```

对于非规格化数：

```text
value = (-1)^S × 2^(-126) × (F / 2^23)
```

需要特别注意：

- `+0` 和 `-0` 数值相等，但位模式不同；
- 非规格化数用于逐渐下溢；
- NaN 有许多不同的位模式；
- 处理 NaN 时必须遵守每道题指定的返回规则；
- `unsigned` 右移补 0，更适合提取浮点字段。

## 9. FP8 E4M3 背景知识

### 9.1 为什么 AI 使用低精度格式

神经网络的权重、激活和梯度通常包含大量数值。使用更少的位保存一个数，可以减少模型占用的存储空间和内存传输量，并让支持低精度计算的处理器一次完成更多运算。

低精度也会减少可表示范围和精度，因此实际 AI 系统通常会配合缩放因子、混合精度计算和更高精度累加。本实验只要求理解 FP8 E4M3 的单个标量编码以及它到 binary32 的转换，不涉及张量缩放或矩阵乘法。

### 9.2 E4M3 位布局

FP8 E4M3 一共 8 位：

```text
7          6              3 2              0
+------------+--------------+----------------+
| 符号 S：1  | 指数 E：4    | 尾数 M：3      |
+------------+--------------+----------------+
```

名称中的 E4M3 表示 4 个指数位和 3 个尾数位，另有 1 个符号位。指数偏置为 7。

普通规格化编码的数值是：

```text
value = (-1)^S × 2^(E-7) × (1 + M / 2^3)
```

当 `E = 0` 时表示零或非规格化数：

```text
value = (-1)^S × 2^(-6) × (M / 2^3)
```

与 binary32 不同，OCP E4M3 没有无穷编码。只有 `S 1111 111` 表示 NaN，因此 `0x7F` 和 `0xFF` 都是 NaN；其余指数为 `1111` 的编码仍是有限数。

### 9.3 重要编码

| E4M3 编码 | 含义 | 转换后的 binary32 位模式 |
| ---: | --- | ---: |
| `0x00` | `+0` | `0x00000000` |
| `0x80` | `-0` | `0x80000000` |
| `0x01` | 最小正非规格化数 `2^-9` | `0x3B000000` |
| `0x08` | 最小正规格化数 `2^-6` | `0x3C800000` |
| `0x38` | `1.0` | `0x3F800000` |
| `0x3C` | `1.5` | `0x3FC00000` |
| `0x7E` | 最大正有限值 `448` | `0x43E00000` |
| `0x7F` | NaN | `0x7FC00000` |

本实验规定：

- 输入 `u8` 的范围为 `0` 到 `255`；
- 必须保留正零和负零；
- `0x7F` 和 `0xFF` 都转换为规范 binary32 NaN `0x7FC00000u`；
- 返回值是 binary32 的 32 位整数位模式，不是 C 的 `float` 值。

完成这道题时，可以按“提取字段、判断类别、换算指数、对齐尾数、组合结果”的顺序思考，但不得调用浮点运算完成转换。

格式定义参考：[OCP Microscaling Formats v1.0](https://www.opencompute.org/documents/ocp-microscaling-formats-mx-v1-0-spec-final-pdf)。FP8 在现代深度学习中的使用背景可参考 [FP8 Formats for Deep Learning](https://arxiv.org/abs/2209.05433)。
